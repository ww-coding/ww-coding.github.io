代码修改与审查

Codex 既可以写代码，也可以审查代码。实际使用时，建议把“修改”和“审查”分成两个阶段。

修改代码

适合让 Codex 做：

  • 新增页面、组件或接口。
  • 修复明确的报错。
  • 补充测试用例。
  • 调整文档结构。
  • 重构局部重复代码。

示例：

帮我在开发工具模块下新增 Codex 文档，保持现有 VuePress 结构。

审查代码

让 Codex 审查时，要明确审查重点：

请 review 当前改动，优先指出 bug、回归风险、边界情况和缺少的测试。

Codex 审查时通常会关注：

  • 是否破坏已有行为。
  • 是否有路径、链接、配置错误。
  • 是否缺少构建或测试验证。
  • 是否有不必要的大范围重构。

推荐流程

  1. 让 Codex 实现需求。
  2. 运行构建或测试。
  3. 查看 git diff。
  4. 让 Codex 做 review。
  5. 修复 review 中确认的问题。
  6. 提交代码。

第 2 步：限制修改范围

只修改 src/data/开发工具/Codex 下面的文档和必要图片。

第 3 步：要求验证

完成后运行 npm run docs:build。

第 4 步：要求审查

请 review 当前改动，重点检查链接路径、图片路径和构建风险。
