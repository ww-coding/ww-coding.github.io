MCP

MCP 可以理解为 Codex 连接外部工具和数据源的一种协议。通过 MCP，Codex 可以访问本地工具、公司系统、文档平台、数据库、浏览器自动化能力等。

MCP 能做什么

  • 查询外部文档。
  • 读取授权后的私有数据。
  • 调用项目专用工具。
  • 操作浏览器或其他应用。
  • 把团队内部系统接入 Codex。

什么时候需要 MCP

  • Codex 需要实时数据，而不是只读本地文件。
  • Codex 需要访问私有系统。
  • Codex 需要调用一个稳定的外部工具。
  • 单靠命令行或文件读写不够。

代码修改与审查

Codex 既可以写代码，也可以审查代码。实际使用时，建议把“修改”和“审查”分成两个阶段。

修改代码

适合让 Codex 做：

  • 新增页面、组件或接口。
  • 修复明确的报错。
  • 补充测试用例。
  • 调整文档结构。
  • 重构局部重复代码。

工作区与 Worktree

Worktree 可以让同一个 Git 仓库同时拥有多个独立工作目录。Codex 做较大任务时，可以在隔离目录中修改代码，避免影响你当前正在编辑的内容。

什么时候使用 Worktree

  • 当前分支上已经有未提交改动。
  • 要尝试一个不确定的方案。
  • 要并行处理多个功能或 bug。
  • 不希望 Codex 的实验性修改影响主工作区。

常见问题

Codex 会自动提交代码吗

一般不会。Codex 可以修改文件，但是否提交通常由你决定。你可以明确要求它提交，也可以自己使用 Git 提交。

Codex 会覆盖我的代码吗

Codex 应该先检查当前工作区状态，并避免覆盖无关改动。为了更安全，可以在需求中明确说：

不要覆盖我已有的未提交改动。

快速开始

Codex 的核心用法是：你提出目标，Codex 读取项目上下文，执行命令或修改文件，然后说明结果。

基本工作方式

  1. 说明你想完成什么。
  2. Codex 先查看项目结构和相关文件。
  3. Codex 给出方案，或直接按你的要求修改。
  4. 修改后运行构建、测试或检查命令。
  5. 你查看 diff，决定是否提交。

常用提问方式

帮我看一下这个项目结构，说明每个目录的作用。

技能 Skills

Skills 是 Codex 的可复用工作流。它可以把某类任务的步骤、规则、参考资料和脚本固定下来，让 Codex 在相似任务中按同一套方法执行。

适合做成 Skill 的场景

  • 经常重复的文档生成流程。
  • 固定格式的代码审查流程。
  • 项目特有的发布检查流程。
  • 某类文件的处理方式，例如 PDF、Word、表格。
  • 团队内部约定的开发规范。

插件适合解决什么问题

版本控制

Codex 本身不替代 Git。它是在你的 Git 仓库里工作，帮你修改文件、查看差异、提交代码或创建 PR。

Codex 和 Git 的关系

  • Git 负责版本控制。
  • Codex 负责理解需求、修改文件、运行命令和解释结果。
  • 你仍然可以用 git status、git diff、git add、git commit 管理版本。

自动化

Codex 可以用于提醒、定时检查、持续跟进等自动化任务。它适合处理“以后某个时间再做”或“周期性检查”的工作。

适合自动化的任务

  • 每天提醒复习某个知识点。
  • 定期检查项目构建是否正常。
  • 周期性跟进某个 issue 或 PR。
  • 在指定时间提醒发布文章。
  • 监控某个条件，满足后通知你。
