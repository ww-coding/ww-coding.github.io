# 快速开始

Codex 的核心用法是：你提出目标，Codex 读取项目上下文，执行命令或修改文件，然后说明结果。

![Codex 基本工作流程](../../../images/codex/codex-overview-flow.svg)

## 基本工作方式

1. 说明你想完成什么。
2. Codex 先查看项目结构和相关文件。
3. Codex 给出方案，或直接按你的要求修改。
4. 修改后运行构建、测试或检查命令。
5. 你查看 diff，决定是否提交。

## 常用提问方式

```text
帮我看一下这个项目结构，说明每个目录的作用。
```

```text
在首页新增一个 Codex 学习入口，保持现有风格。
```

```text
帮我修复这个报错，先定位原因，再改代码。
```

```text
请审查当前改动，重点看是否有 bug、回归风险和缺少测试。
```

## 让 Codex 更好工作的提示

- 说明目标，不只说明操作。
- 给出期望位置，例如“放在开发工具模块下”。
- 说明约束，例如“不要改首页样式”“不要提交代码”。
- 如果只是想讨论，明确说“先别改代码”。
- 如果想让 Codex 执行，直接说“执行”或“按方案实现”。

## 第一次使用步骤

### 第 1 步：让 Codex 了解项目

```text
先看一下这个项目结构，告诉我它是怎么组织页面和导航的。
```

### 第 2 步：提出一个小目标

```text
在开发工具模块下新增一篇 Codex 快速开始文档，风格参考已有 Git 文档。
```

### 第 3 步：确认修改范围

```text
只修改 Codex 文档和侧边栏配置，不要改首页。
```

### 第 4 步：执行并验证

```text
执行，并在完成后运行构建命令验证。
```

### 第 5 步：查看结果

```bash
git status
git diff
```

看完差异后，再决定是否提交。

## 不适合模糊表达

不推荐：

```text
优化一下。
```

推荐：

```text
优化这篇 Codex 文档的结构，让新手能按顺序学习，不要改导航。
```
