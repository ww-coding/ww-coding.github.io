# Codex

Codex 是 OpenAI 的 AI 编程助手，可以帮助你阅读代码、修改代码、排查问题、写文档、跑测试、做代码审查，也可以通过插件、技能、MCP 和自动化扩展工作流。

这个模块按实际使用场景整理 Codex 的核心功能。

![Codex 基本工作流程](../../images/codex/codex-overview-flow.svg)

## 学习路线

1. [快速开始](./Codex/快速开始.md)：了解 Codex 能做什么，以及第一次使用时怎么提需求。
2. [版本控制](./Codex/版本控制.md)：理解 Codex 和 Git、分支、提交、PR 的关系。
3. [工作区与 Worktree](./Codex/工作区与Worktree.md)：学习如何隔离任务改动，避免影响当前代码。
4. [代码修改与审查](./Codex/代码修改与审查.md)：让 Codex 修改代码、解释改动、检查风险。
5. [技能 Skills](./Codex/技能Skills.md)：用可复用流程增强 Codex 的专业能力。
6. [插件 Plugins](./Codex/插件Plugins.md)：用插件打包技能、工具、MCP 和配置。
7. [MCP](./Codex/MCP.md)：让 Codex 连接外部系统和私有数据源。
8. [自动化](./Codex/自动化.md)：创建提醒、定时检查和持续跟进任务。
9. [常见问题](./Codex/常见问题.md)：整理使用中最容易混淆的问题。

## 适合用 Codex 做什么

- 阅读陌生项目，快速理解模块职责。
- 添加小功能、修复 bug、补充测试。
- 重构局部代码，但保留原有行为。
- 生成文档、整理学习笔记、补充使用说明。
- 做代码审查，发现风险、遗漏测试和边界问题。
- 通过 MCP 或插件连接更多工具。

## 使用原则

- 需求越具体，结果越稳定。
- 修改代码前，先让 Codex 看项目结构。
- 重要改动要跑测试或构建验证。
- 不确定的地方让 Codex 先解释方案，再执行。
- 涉及版本控制时，先看 `git status`，避免覆盖已有改动。

## 一次完整操作步骤

1. 先说清楚目标，例如“在开发工具模块下新增 Codex 教程”。
2. 说明修改范围，例如“只改 `src/data/开发工具` 和侧边栏配置”。
3. 让 Codex 查看项目结构，确认应该放在哪个模块。
4. 确认方案后执行修改。
5. 运行构建或测试命令，例如 `npm run docs:build`。
6. 查看 Codex 总结和 Git diff。
7. 确认没问题后再提交。
